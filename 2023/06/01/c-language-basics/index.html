C语言入门：从指针卡住到慢慢想明白

发表于2023-06-01|更新于2026-10-08|编程学习
|阅读量:

为什么第一门课是 C

大一上学期开的是 C 语言。老师给的理由很直接：先把内存这件事搞清楚，后面学什么都省力。当时我不太信，现在回头看，这句话是对的。

C 语言没有太多语法糖，写出来短小，但要求你知道每一行到底在干什么。

第一个坎：编译和运行是两件事

最开始的困惑不在语法，而在流程。写一个 .c 文件，它不能直接双击运行，得先编译：

我第一次写错是在文件名上，把 hello.c 存成了 hello.c.txt，编译报错说找不到文件，我盯着屏幕找了半小时。后来学会了先 ls 一下，确认文件真的在那儿。

第二个坎：指针

指针大概是劝退最多人的地方。我卡了整整两周。

真正让我想通的是一句话：指针是一个变量，这个变量里存的是地址。 就这么简单，之前我一直把它当成某种神秘的符号。

& 是取地址，* 是按地址取值。这两个符号在一开始总被我搞反。我的办法是在纸上画内存格子：一边写变量名，一边写地址，一边写值，画上十几次之后手就有感觉了。

第三个坎：数组和字符串

C 里的字符串其实是字符数组，以 \0 结尾。这个设计让很多事情变得需要小心。

sizeof(s) 会得到 4 而不是 3，原因就在这个结尾符。我一开始照着别的语言的直觉写，怎么算都对不上，后来才明白要多算一位。

还有一个常见的坑是数组越界。C 不会替你检查，写超了也照常运行，只是可能改到别的内存，然后在完全无关的地方报错。这种 bug 找起来最费时间，所以现在我写完循环一定要看一眼边界条件。

一点经验

  • 编译器的报错要读完。C 的报错信息比较详细，行号和原因都有，比瞎猜快得多。
  • 小步运行。不要一次写两百行再编译，写十行就跑一次。
  • 画内存图。指针和数组这类东西，纸上画一遍胜过盯着代码看十遍。

现在我用别的语言时，遇到内存相关的问题还会想起这门课。C 教给我的与其说是语法，不如说是”知道机器在做什么”的习惯。
